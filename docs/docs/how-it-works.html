HUFF is a native video instrument. The HTML window is the control surface, Rust owns the state and media systems, and wgpu owns the image that ultimately feeds the screen, recording, export, and external outputs.

ON THIS PAGE

What HUFF is

At the highest level, HUFF takes one authoritative visual source, transforms it through a chain of glitch, temporal, and compositing operations, and produces a committed final image called Program. That Program image is what other subsystems trust. It can be recorded, exported, or published to Syphon or Spout.

The current system in plain language

Control surface

The HTML interface is a remote control. Sliders, toggles, and overlay panels send commands into Rust. The interface itself is not the renderer.

Canonical state

Every major feature—UI, automation, presets, MIDI, OSC, routing, recording, and export—refers to the same canonical parameter registry. That registry is the official source of truth for value, default, range, and type.

Source ownership

HUFF always knows which live source is active. A file source and a camera source do not compete invisibly. Transport, decoder progress, audio, and recovery are native responsibilities, not browser assumptions.

Temporal memory

Several HUFF effects rely on time, not just the current frame. Native HUFF therefore owns real temporal image resources: a history ring, a persistent Field Store, feedback targets, and Flow-related resources.

Program and Monitor

Program is the authoritative final image. Monitor is what the local output window displays. They are related but not identical. Monitor can inspect Program, Clean, or Field Store while external outputs continue using Program.

The native image pipeline

The current engine is not a free-form node editor. It is a stable pipeline with named responsibilities and constrained recipe switches. That keeps HUFF readable, saveable, and predictable while still allowing multiple internal routes.

Quick intuition. If you only remember three things, remember these: HUFF has a current source, HUFF has temporal image memory, and HUFF ends in a Program image that downstream systems trust.

What a newcomer should understand first

  1. Source is the current incoming file or camera image.
  2. Effects transform that source through glitch, scanline, flow, feedback, and compositing stages.
  3. Temporal memory gives those effects access to previous frames and persistent image stores.
  4. Program is the final committed image.
  5. Outputs such as recording, export, Syphon, and Spout are downstream of Program.

What is complete and what is still provisional

AreaStatusHow to read that status
Native rendering, sources, core effectsIntegratedThe migration is structurally complete. The application runs as a native instrument.
Live recording, still export, deterministic exportIntegratedThe systems exist and work, but still benefit from broader local test coverage.
Routing recipesIntegratedRecipes already alter legal paths inside the engine and can expand with future features.
MIDI, OSC, projects, presets, automationIntegratedThese form a real control/state workflow, not just a prototype shell.
Export queueProvisionalUseful infrastructure, but still subject to future keep/hide/remove decisions.
Parity LabCalibration scaffoldHelpful for reference and testing, but not a public-facing artistic feature.
Interop LabResearchExplains and measures the current copy path; it does not claim zero-copy output.
