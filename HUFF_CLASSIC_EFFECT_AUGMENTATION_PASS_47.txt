HUFF CLASSIC EFFECT AUGMENTATION PASS 47
LIVE LUMA KEY GPU HANDOFF + SCRATCH BUDGET
2026-08-11

BASELINE
- Direct continuation of HUFF Classic Pass 46.
- Pass 41A remains the accepted Classic foundation.
- Passes 42/43 Solarize visual behavior remains protected.
- Flow remains frozen/protected.

RUNTIME REPORT THAT TRIGGERED THIS PASS
- Luma Key alone, TARGET=COMPOSITE / KEY SRC=LIVE, reduced runtime from roughly
  60 FPS to roughly 52 FPS on the target Mac.
- This isolated Luma as an independent front-stage bottleneck.

ROOT CAUSE
- The accepted LIVE/COMPOSITE Luma path still crossed Canvas2D's CPU boundary:
  bounded source draw -> getImageData -> JS luma/key transform -> putImageData
  -> scaled keyed patch presentation.
- Previous passes reduced duplicate work but could not remove the synchronous
  Canvas/GPU -> CPU -> Canvas handoff.
- The old workspace was width-limited only, allowing portrait/tall sources to
  exceed the intended processing budget substantially.

PASS 47 CHANGES
1. LIVE/COMPOSITE Luma now gives a bounded WebGL 1 patch accelerator first
   refusal. HUFF Classic remains Tauri v1 + p5.js/Canvas2D; this is not wgpu.
2. Successful GPU Luma frames use no getImageData(), putImageData(), readPixels(),
   gl.finish() or gl.flush(). The generated keyed patch is copied into a bounded
   Canvas2D cache once per decoded source frame / key-shape change.
3. A one-time runtime parity probe tests the actual WebGL -> Canvas2D alpha
   handoff against the established CPU composite for both X-FADE and SOFT ADD.
4. The existing Solarize WebGL context is tested first. If alpha semantics fail,
   Pass 47 lazily tests a second Luma-only context with premultipliedAlpha=false.
5. GPU Luma is enabled only if a tested alpha convention remains within the
   strict calibration tolerance. Otherwise HUFF automatically uses the accepted
   CPU path.
6. The CPU fallback now collapses Clip/Gain/Invert/Cleanup/Density into one
   256-entry final key LUT rather than recomputing key math for every pixel.
7. Luma scratch sizing is now bounded by both long edge and pixel count:
     COMPOSITE <= 640 long edge and approximately 640x360 pixels
     CORRUPT/SCAN object plane <= 320 long edge and approximately 320x180 pixels
   Examples: 1920x1080 -> 640x360; 1080x1920 -> 360x640.
8. Profiler adds GPU Luma frames/fallbacks, calibration context/mode/error, and
   bounded Luma GPU patch build/reuse/fallback counters.

EXPLICITLY UNCHANGED
- Luma control model and accepted matte polarity.
- TARGET semantics: COMPOSITE / CORRUPT / SCAN.
- KEY SRC semantics: LIVE / STENCIL.
- X-FADE and SOFT ADD behavior.
- Solarize THRESHOLD, LUMA QUANTIZE and FLUIDITY transforms.
- Feedback/Persistence.
- Flow.
- Playback cadence. No frame skipping, hold, strobe or rate manipulation.
- Native Tauri/Syphon/Spout runtime and factory presets.

RUNTIME ACCEPTANCE
Primary test: reproduce the isolated Luma test that was ~52 FPS in Pass 46.
Profiler expectations on a successful accelerated LIVE/COMPOSITE path:
- gpu color = ON
- gpu luma advances
- gpu lu fall remains 0
- luma gpu build/reuse advances
- luma read/xform/upload should remain at zero for successful GPU LIVE frames
- gpu lu cal reports a selected context/mode with max difference <= 2

If calibration rejects both WebGL alpha conventions, HUFF deliberately falls
back to CPU rather than changing the visual output. Record the gpu lu cal line.
